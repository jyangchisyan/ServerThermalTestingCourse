# 第三課之二：訓練集與測試集

## 兩種資料用途不同

```text
訓練資料 → 用來學習或設計規則
測試資料 → 最後評分，模擬沒看過的考題
```

如果反覆查看測試答案並調整規則，測試集就不再是未見資料，得到的成績也會過度樂觀。

## 為什麼要先打亂

目前樣本原本按照：

```text
正常、正常、異常、異常
```

直接切片可能讓某一組幾乎只有單一標籤。`shuffle()` 會改變順序，但不會改變樣本數量或標籤數量。

## 固定亂數種子

```python
random_generator = Random(42)
random_generator.shuffle(samples)
```

相同種子會產生相同的打亂結果，讓實驗能重現。數字 42 只是示範值。

## 先複製再打亂

```python
shuffled_samples = samples.copy()
```

這樣不會破壞原始資料順序。整理後的 `split_samples()` 會先複製、再打亂、最後切片。

## 目前資料仍太少

四個樣本切成三筆訓練、一筆測試，評估結果很不穩定。更重要的是，同一段時間序列產生的相鄰樣本非常相似。未來應以整段情境或整台伺服器為單位切分，避免相似資料同時出現在訓練集與測試集，造成資料洩漏（data leakage）。
